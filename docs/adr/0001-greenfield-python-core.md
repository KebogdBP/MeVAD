# ADR 0001: Greenfield Python Core

**Статус:** accepted
**Дата:** 2026-07-25

## Контекст

Новый репозиторий MeVAD был создан без истории и исходного кода прежнего CLI.
Project Vision требует, чтобы CLI, API и worker использовали одно независимое
ядро.

## Решение

- Разрабатывать core с нуля в Python-пакете с `src`-layout.
- Поддерживать Python 3.11 и новее.
- Не добавлять runtime-зависимости до появления реальной границы интеграции.
- Оставлять ввод, вывод и `argparse` в CLI adapter.
- Возвращать из core типизированные значения и доменные исключения.
- Выполнять сетевой доступ и запуск внешних процессов только через adapters.
- Рассматривать старый CLI как справочный источник, а не основу репозитория.

## Последствия

Плюсы:

- отсутствует неявная зависимость от терминального меню;
- core можно будет использовать из CLI, API и worker;
- security-границы появляются до подключения `yt-dlp`;
- тесты не требуют сети или медиаплатформ.

Минусы:

- прежние рабочие сценарии нужно реализовать и подтвердить заново;
- интеграция с `yt-dlp` не появится в самом первом инкременте;
- решения о lock tool и лицензии остаются отдельными ADR.
